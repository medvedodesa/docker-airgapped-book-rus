## Подготовка (за 3–7 дней)

- [ ] Проверить путь обновления: `bash gitlab-upgrade-path.sh <текущая> <целевая>`
- [ ] Убедиться что все промежуточные версии скачаны в закрытый контур
- [ ] Проверить release notes целевой версии на breaking changes
- [ ] Проверить обновление на тестовой среде с копией продакшен-БД
- [ ] Уведомить пользователей о плановом окне обслуживания

## Непосредственно перед обновлением

- [ ] Создать полную резервную копию: `gitlab-backup create`
- [ ] Убедиться что резервная копия завершилась: `ls -la /var/opt/gitlab/backups/`
- [ ] Записать текущую версию: `gitlab-rake gitlab:env:info | grep version`
- [ ] Проверить состояние сервисов: `gitlab-ctl status`
- [ ] Нет pending миграций: `gitlab-rake db:migrate:status | grep down | wc -l`
- [ ] Свободно >10 ГБ на диске: `df -h /var/opt/gitlab`

## Обновление

- [ ] Установить пакет промежуточной версии (если нужна): `dpkg -i gitlab-ce_XX.XX.XX_amd64.deb`
- [ ] Дождаться завершения миграций БД (журнал: `/var/log/gitlab/gitlab-rails/production.log`)
- [ ] Проверить работоспособность промежуточной версии
- [ ] Установить пакет целевой версии: `dpkg -i gitlab-ce_XX.XX.XX_amd64.deb`
- [ ] Проверить применение конфигурации: `gitlab-ctl reconfigure`

## Проверка после обновления

- [ ] `gitlab-ctl status` — все сервисы запущены
- [ ] `gitlab-rake gitlab:check` — нет критических ошибок
- [ ] Открыть UI — GitLab загружается, версия правильная
- [ ] Выполнить тестовый коммит в тестовый репозиторий
- [ ] Запустить тестовый конвейер CI/CD
- [ ] `docker pull harbor.internal.company.local/library/alpine:3.19` — успешно

## Если что-то пошло не так

- [ ] Остановить GitLab: `gitlab-ctl stop`
- [ ] Установить предыдущую версию пакета
- [ ] Восстановить резервную копию: `gitlab-backup restore BACKUP=<дата>`
- [ ] Проверить: `gitlab-ctl start && gitlab-rake gitlab:check`
